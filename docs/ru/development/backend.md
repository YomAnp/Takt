# Разработка сервера

[На главную](../index.md) · [English](../../en/development/backend.md)

Сервер находится в `apps/backend/`. Для работы нужны Python 3.12.12, uv 0.10.2 и запущенный Docker с Compose. PostgreSQL 17 запускается отдельным контейнером; данные сохраняются в томе `postgres-data`.

## Запуск

Из корня репозитория:

```sh
python scripts/dev.py start
```

Команда поднимает БД, устанавливает зависимости из `apps/backend/uv.lock`, применяет миграции Alembic и запускает API с перезагрузкой при изменении исходников. API доступен на `http://127.0.0.1:8000`, OpenAPI и форма запросов — на `http://127.0.0.1:8000/docs`. Остановка сервера — Ctrl+C; контейнер останавливается командой `docker compose stop db`.

Параметры локальной БД приведены в `env.example`. Для другого подключения задаётся переменная окружения `TAKT_DATABASE_URL`; часовой пояс задаётся через `TAKT_TIME_ZONE`, по умолчанию `Europe/Moscow`. Файл `env.example` служит примером и автоматически не загружается. Локальные реквизиты контейнера предназначены для разработки; порт БД доступен только через `127.0.0.1`.

## Данные и расчёт

`users` хранит пользователя, роль `member` или `admin` и признак активного доступа. `work_schedules` хранит местное время окончания дня с датой начала действия. `set_schedule` меняет его с текущей даты в одной транзакции с `audit_log`; повтор того же значения не создаёт лишнюю запись. Прошлые дни используют прежнее правило.

`attendance` хранит интервалы присутствия, `breaks` — явно отмеченные перерывы. PostgreSQL запрещает пересечения интервалов одного пользователя, пересечения перерывов и выход перерыва за границы присутствия. Незакрытый интервал не получает вымышленное время ухода.

`get_summary` читает сохранённые записи и передаёт их расчётному ядру. Сотрудник имеет доступ к своему учёту; активный администратор — к индивидуальному учёту сотрудников. Заблокированный аккаунт доступа не имеет.

Время хранится в `timestamptz`; длительности рассчитываются в UTC, дата прихода и контрольное окончание — в часовом поясе приложения. Интервал целиком относится к дате прихода, включая уход после полуночи. Перерывы входят в общее время и отдельно суммируются для личной статистики. Открытый интервал текущего дня даёт предварительный итог. Для прошлого открытого дня итог неизвестен до подтверждения ухода; отдельно возвращается сумма закрытых интервалов. Предварительный расчёт ухода использует выбранное окончание без записи в БД.

`POST /api/v1/time/day` рассчитывает переданные интервалы по времени окончания дня. Расчёт по длительности `POST /api/v1/time/calculate`, `time_goals` и `set_goal` сохраняют прежний формат данных; они не задают настройку нового рабочего дня. Перерывы в обоих расчётах входят в общее время. Подробные [правила учёта](../product/time-accounting.md) содержат примеры.

HTTP предоставляет расчёт переданных интервалов и проверки работоспособности. Операции с сохранёнными личными данными остаются во внутреннем слое приложения и требуют проверенного пользователя.

## Команды учёта

Внутренние команды получают проверенного пользователя и серверное время в `now`. Приход и уход дополнительно принимают `occurred_at` — фактическое время, если отметка внесена позднее. Оно не может быть в будущем; журнал отдельно сохраняет `recorded_at`.

| Операция | Назначение |
| --- | --- |
| `check_in` | Начать присутствие после сохранения времени окончания дня |
| `start_break` | Начать перерыв внутри открытого интервала |
| `end_break` | Завершить указанный текущий перерыв |
| `preview_checkout` | Получить итог для подтверждения и признак завершения перерыва |
| `check_out` | После явного подтверждения завершить присутствие и текущий перерыв вместе |
| `reopen_attendance` | Отменить последний уход и восстановить состояние до него |
| `current_attendance` | Прочитать актуальное открытое присутствие после повторного открытия приложения |
| `pending_departure` | Получить прошлый открытый день и допустимость ухода по сохранённому времени |

Каждая изменяющая команда получает `request_id`. Успешный результат сохраняется в `time_command_receipts` в одной транзакции с отметками и `audit_log`. Повтор того же запроса возвращает исходный результат; использовать его идентификатор для другой операции или других параметров нельзя. Отклонённая команда не оставляет частичных изменений.

Для существующего интервала передаётся `expected_revision`. Если запись изменилась на другом устройстве, команда отклоняется с `stale_revision`: данные и подтверждение нужно обновить. При уходе сервер требует `confirmed`; `will_end_break` в предварительном результате позволяет явно сообщить о завершении перерыва.

Отмена ухода восстанавливает и автоматически завершённый им перерыв. Самостоятельно завершённые ранее перерывы остаются закрытыми. Если после ухода уже появился следующий интервал присутствия, отмена отклоняется, чтобы не создать пересечение. Изменения сохраняются в журнале с состоянием до и после команды.

Сохранённый ответ на повтор команды не заменяет текущее состояние: после восстановления связи вызывающий код читает `current_attendance`. Например, повтор старой команды ухода после её отмены возвращает прежний ответ, но не закрывает присутствие снова.

Команды изменяют только собственное присутствие пользователя. Право администратора читать индивидуальный учёт не даёт этим командам права менять чужие отметки.

`pending_departure` ничего не завершает автоматически. Подтверждается сохранённое время окончания того дня либо фактический уход. Предложенное время недоступно, если оно раньше уже внесённых событий. Перед новым приходом требуется закрыть открытый интервал.

## Проверки

```sh
python scripts/dev.py check
```

Команда создаёт отдельную БД `takt_test` и запускает Ruff, mypy и pytest. Тесты применяют и откатывают миграции; тестовые таблицы пересоздаются. Рабочая БД `takt` при проверках не используется.

Для тестов в другом окружении задаётся `TAKT_TEST_DATABASE_URL`. Имя тестовой БД должно заканчиваться на `_test`; иначе проверки прекращаются. Проверяются необязательные перерывы без остановки общего времени, пропущенный уход, фактические отметки, переход через полночь, смена окончания без изменения прошлых дней, доступ администратора, ограничения PostgreSQL и конфликты одновременных записей. Те же проверки выполняются в GitHub Actions.
